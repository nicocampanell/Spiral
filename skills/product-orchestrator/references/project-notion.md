# Project Notion record

When using Notion, give each project a separate home with nested documents. Resolve and record the canonical project home URL/ID, child-document map and relevant account/context. Use an existing home supplied or clearly mapped to the project; do not pick an unrelated page because it was recently used. When the destination or account is ambiguous, ask for the project home or parent location. Creating pages needs a verified authorized parent; do not scatter duplicates across the workspace.

## Project hierarchy

Keep the project home concise: current vision, selected direction, status, next meaningful decision/milestone and links to its nested documents. Reuse existing equivalent documents instead of imposing a parallel tree. When new documents are needed, start with:

- **Vision & Scope:** the project owner's confirmed intent, intended user, core flow, constraints and acceptance criteria.
- **Research & Perspectives:** sources, findings, implications, uncertainty and labeled hypothetical journeys.
- **Design & Decisions:** distinct directions, selected/rejected alternatives, reasons and important product changes.
- **Delivery & Verification:** scoped work, owners/dependencies, working milestones, actual checks, evidence and remaining gaps.

Create a child document when it has substantive content; do not generate empty template pages or new databases for every task. Keep each project's documents under that project's home. Preserve existing names/structure where they serve the same purpose.

Use the local Composio CLI for Notion work in terminal/Codex, following the installed Composio fast/CLI workflow. Discover a needed tool once, inspect its schema as needed, and reuse verified tool/account choices in the current run. Do not embed credentials or a personal/work account default in this skill. If the CLI is unavailable or a capability is unsupported there, use the supported fallback and explain the limitation.

## Keep decisions trustworthy

Read the current page before updating it. Preserve the project owner's authored material and existing structure. Keep these categories visibly distinct within the chosen structure:

- **Confirmed vision:** intended user, core problem, distinctive experience and the project owner's explicit choices.
- **Research and perspectives:** source links, findings, implications, uncertainty and clearly labeled simulated journeys.
- **Decisions:** selected direction, rejected alternatives and reasons; date and criteria revision for consequential changes.
- **Open questions/assumptions:** owner, consequence and what resolves each uncertainty.
- **Delivery:** scoped tasks, dependencies, owners, status and upcoming user decision/milestone.
- **Verification:** actual checks/outcomes, version identity, remaining gaps and evidence links where accessible.

These categories live in the project home and appropriate nested documents, not one ever-growing flat page. They do not authorize a new database or unrelated reorganization. The root lead owns writes to the canonical hierarchy; specialists and delegated coordinators send proposed updates/evidence to it. Do not have several agents edit the same Notion document concurrently.

## Update at useful moments

Record meaningful settled changes after an interview round, direction selection, scope/criteria amendment, substantive milestone or verification result. Batch related updates; do not log every tool call or repeatedly ask permission for routine maintenance of the already-authorized project record. State when a proposal is still pending; never silently turn an agent recommendation into the project owner's decision.

Use targeted section/block updates supported by the actual tool, not a blind full-page replacement. Read back the affected content to verify it saved and preserved unrelated material. On an uncertain write result, inspect the actual page before retrying; never blindly replay through another surface. A failed or unavailable Notion write remains pending, with a local note containing the exact intended delta and destination. Never claim it synced.

Notion is the shared product/decision record. The repository and current runtime remain the source of truth for code and actual check results; keep a local run checkpoint with project home/child IDs, criteria revision and pending sync. If those records conflict, inspect reality, preserve the history and reconcile visibly instead of trusting an old all-done checkbox.

Do not paste credentials, private raw transcripts or sensitive debug payloads into the page. This workflow authorizes only project-record changes within the user's task; it does not authorize external messages, unrelated workspace reorganization or publication.
